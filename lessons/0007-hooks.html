B5 Týden 3 Blok B: Agentní paradigma

Hooks

Deterministické guardrails — co se musí (ne)stát vždy, bez ohledu na to, co agent chce. Skill vyvoláš ty; hook se spustí sám.

1 — Jádro

CLAUDE.md řekne agentovi "necommituj přímo do main". Agent to většinou poslechne — ale prochází to modelem, a model je pravděpodobnostní. Někdy poslechne, někdy ne. Když potřebuješ jistotu, že se něco nestane, není správná vrstva instrukce. Je to hook.

Hook je shell skript, který harness spustí automaticky při určité události — než agent zavolá nástroj, poté co upraví soubor, když session končí. Neprochází modelem. Je to obyčejný kód: spustí se, vrátí exit code, a podle něj se akce buď povolí, nebo zablokuje. Vrstva 3 rámce pěti otázek: "Jaké guardrails jsou deterministické?"

Jedno pravidlo

Když spolehlivost nesmí záviset na tom, co si model "myslí", je to hook. Hook nežádá agenta, aby se choval správně — fyzicky mu nedovolí chovat se špatně.

2 — Hook vs. skill: kdo drží spoušť

Skill a hook mohou obsahovat tentýž postup. Liší se v jediné, ale zásadní věci: kdo je spouští a jestli se to dá obejít.

  Skill (harness) Hook (guardrail)
Kdo spouští Ty, přes /název Harness, automaticky při události
Prochází modelem? Ano — je to prompt Ne — je to shell skript
Dá se zapomenout? Ano — musíš ho vyvolat Ne — spustí se vždy
Umí zablokovat akci? Ne — jen navrhuje postup Ano — exit code 2 akci zastaví
Charakter Pozitivní: „udělej tohle" Negativní: „tohle se nesmí"
Klíčové rozlišení

Skill je pozitivní architektura — dáváš agentovi schopnost něco udělat na povel. Hook je negativní architektura — definuješ hranici, kterou agent nemůže překročit, ať chce nebo ne. Skill rozšiřuje; hook omezuje. Zpět k B1: harness vs. guardrails.

3 — Anatomie hooku

Hook se konfiguruje v settings.json: navážeš shell příkaz na událost. Nejdůležitější události v životním cyklu:

PreToolUse Než agent zavolá nástroj — může akci zablokovat (exit 2)
PostToolUse Poté co nástroj doběhl — např. spustit formatter po editaci
UserPromptSubmit Když odešleš prompt — validace nebo doplnění kontextu
Stop Když agent končí odpověď — např. ověřit, že testy jsou zelené
SessionStart / SessionEnd Začátek a konec session — setup, úklid, log

Hook dostane na stdin JSON s daty události (jaký nástroj, s jakými argumenty). Rozhodne se a vrátí exit code. Pro PreToolUse platí jednoduché pravidlo: exit 2 = blokuj, cokoliv jiného = povol. Text na stderr se ukáže agentovi jako důvod.

# .claude/settings.json — zablokuj přímý commit do main { "hooks": { "PreToolUse": [{ "matcher": "Bash", "hooks": [{ "type": "command", "command": ".claude/hooks/guard-main.sh" }] }] } } # .claude/hooks/guard-main.sh #!/usr/bin/env bash cmd=$(jq -r '.tool_input.command') branch=$(git branch --show-current) if [[ "$branch" == "main" && "$cmd" == *"git commit"* ]]; then echo "Zakázáno: commit přímo do main. Založ větev." >&2 exit 2 # exit 2 = zablokuj akci fi exit 0 # cokoliv jiného = povol

Žádná interpretace. Žádné "většinou". Skript vidí commit do main, vrátí 2, akce se nestane. Vždy, deterministicky.

4 — Kdy použít hook (a kdy ne)

Použij hook ✓

  • Kritický invariant, který nesmí selhat (žádný commit do main)
  • Něco se musí stát automaticky (formátovat po každé editaci)
  • Bezpečnostní hranice (nikdy nemazat data/)
  • Ověření na konci (testy musí být zelené, než agent skončí)
  • Spolehlivost nesmí záviset na tvé paměti ani na modelu

Nedělej z toho hook ✗

  • Postup, který chceš spouštět, jen když se rozhodneš → skill
  • Znalost projektu → CLAUDE.md
  • Preference, kde občasná odchylka nevadí → CLAUDE.md
  • Něco pomalého, co by blokovalo každou akci
  • Pravidlo, které se často mění a experimentuješ s ním

Hook je nejsilnější a zároveň nejdražší vrstva: běží při každé události, na kterou ho navážeš, a když je pomalý nebo chybný, brzdí nebo blokuje veškerou práci. Proto ho rezervuj pro to, co se opravdu musí vynutit — ne pro to, co by bylo hezké mít.

5 — Proč na tom záleží: deterministický vs. probabilistický

Tohle je jádro celé lekce. CLAUDE.md, skill i prompt sdílejí jednu vlastnost: prochází modelem. Model je pravděpodobnostní — instrukci splní s vysokou pravděpodobností, ne s jistotou. Pro 95 % věcí to stačí. Pro zbylých 5 % — data, bezpečnost, nevratné akce — 95 % není dost.

Hook tenhle strop probourá, protože neprochází modelem. Je to shell skript. Buď se spustí a vrátí 2, nebo ne. Není tam žádná interpretace, žádná teplota, žádné "agent to tentokrát pochopil jinak". Determinismus je celá pointa.

Mentální model

Ptej se: „Co se stane, když model tuhle instrukci v jednom z tisíce běhů ignoruje?" Když je odpověď „nic hrozného" → stačí CLAUDE.md. Když je odpověď „smazaná data / rozbitý main / uniklý token" → potřebuješ hook. Determinismus kupuješ přesně tam, kde je selhání nepřijatelné.

6 — Historický kontext

Hooks nejsou nic nového — je to CI/CD tradice přenesená k agentovi:

  • Git hooks (pre-commit, pre-push). Přesně stejný nápad: skript, který se spustí při události a může akci zablokovat. Claude Code hook je git hook pro akce agenta.
  • CI/CD pipelines (Jenkins, GitHub Actions). Deterministické brány: testy neprošly → merge se nestane. Žádné „většinou". Hook je tatáž brána, jen o krok dřív — u samotné akce.
  • Linters a pre-commit frameworky. Automatická vynucená pravidla, ne doporučení. Vývojáři je znají desítky let.
  • Assertions a design by contract. Invariant, který se ověřuje za běhu a při porušení zastaví program — ne se jen doufá, že platí.

Pro publikum je to úleva: guardrails znají z CI. Nová je jen věc, kterou hlídají — akce agenta místo commitu člověka.

7 — Tři příklady

Vědec-kodér

Pracuje s cennými naměřenými daty v data/raw/, která nejde znovu pořídit. Do CLAUDE.md napsal „nikdy neupravuj raw data" — a jednou to agent přesto udělal při „úklidu". Teď má PreToolUse hook: jakýkoliv zápis nebo smazání pod data/raw/ → exit 2. Instrukce se dá ignorovat; hook ne. Data jsou fyzicky chráněná.

RSE vývojář

Tým vyžaduje, aby veškerý Python kód prošel ruff a testy před koncem každé úlohy. Místo aby to připomínal v každém promptu, má dva hooky: PostToolUse spustí formatter po každé editaci, Stop hook nepustí agenta „hotovo", dokud pytest není zelený. Kvalita se nevynucuje disciplínou — vynucuje se harnessem.

Manažer / PI

Řeší otázku od security týmu: „Jak zaručíte, že agent nepushne tokeny do repozitáře?" Odpověď není „řekli jsme mu to". Je to PreToolUse hook, který skenuje diff na secrets a zablokuje commit. Hook je auditovatelný artefakt — skript v repu, který jde ukázat auditorovi. Instrukce v promptu se auditovat nedá; shell skript s exit code ano.

8 — Propojení na ostatní lekce

  • B1 — Harness vs. Guardrails: Hook JE guardrail — negativní architektura. Tahle lekce je konkrétní implementace toho, co B1 zavedla teoreticky. Skill (B4) je harness, hook je guardrail; společně tvoří obě strany.
  • B4 — Skills: Ostrá hranice se láme tady. Tentýž postup: jako skill ho vyvoláš ty (dá se zapomenout), jako hook se spustí sám (nedá se obejít). Rozdíl není v postupu — je v tom, kdo drží spoušť.
  • B3 — Memory a CLAUDE.md: CLAUDE.md instrukci model interpretuje; hook ji vynutí. Pro kritické invarianty nepatří do CLAUDE.md — patří do hooku. Když agent instrukci z CLAUDE.md ignoruje, je to signál povýšit ji na hook.
  • A1 — TDD: „Testy musí být zelené, než skončíš" je Stop hook. Red-green disciplína vynucená harnessem, ne dobrou vůlí.

9 — Nejčastější nepochopení

Nepochopení 1

„Silnou instrukci v CLAUDE.md („NIKDY nedělej X!!!") agent poslechne stejně spolehlivě jako hook."

Skutečnost

Velká písmena a vykřičníky mění pravděpodobnost, ne jistotu. Instrukce pořád prochází modelem. Hook neprochází — je to kód s exit code. Rozdíl mezi „skoro vždy" a „vždy" je přesně ten rozdíl, kvůli kterému hooky existují. Pro kritické věci není „skoro" dost.

Nepochopení 2

„Hooky jsou pokročilá věc — přidám jich radši spoustu, ať jsem v bezpečí."

Skutečnost

Každý hook běží při své události — a když je pomalý nebo chybný, brzdí nebo blokuje veškerou práci. Špatný hook je horší než žádný: tiše rozbije workflow a těžko se hledá. Měj málo hooků, které hlídají to, co se opravdu nesmí stát. Guardrail není dekorace.

Nepochopení 3

„Hook je jen automaticky spuštěný skill."

Skutečnost

Skill radí postup agentovi (prochází modelem, agent ho může upravit). Hook je mimo model — vykoná se přesně tak, jak je napsaný, a umí akci zablokovat, což skill neumí. Automatizace není jediný rozdíl; determinismus a schopnost blokovat jsou to podstatné.

10 — Spicy teze

Když někdo řekne „nemůžu agentovi věřit, že nesmaže něco důležitého" — nemá problém s AI. Má problém s tím, že jeho kritické invarianty nikdy nebyly vynucené, jen doufané. Agent tu díru jen zviditelnil. Zralý tým své hranice nepíše do promptu jako prosbu — zadrátuje je jako guardrail. Důvěra není strategie; determinismus ano.

13 — Co dál

Co musíš znát před touto lekcí:

  • B1 — Harness vs. Guardrails — hook je konkrétní guardrail. Bez rozlišení pozitivní/negativní architektury tahle lekce nedává smysl.
  • B4 — Skills — skill je protipól hooku. Rozdíl „kdo drží spoušť" je jádro obou lekcí.

Praktický úkol (25 minut): Vyber jeden kritický invariant ve svém projektu — něco, co se nesmí stát (smazání dat, commit do main, push tokenu). Napiš minimální PreToolUse hook, který to zablokuje: shell skript, který přečte JSON ze stdin, zkontroluje podmínku a vrátí exit 2. Otestuj, že agenta opravdu zastaví. Pak si zkus rozdíl: dej tentýž postup do CLAUDE.md a pozoruj, že „skoro vždy" není „vždy".
