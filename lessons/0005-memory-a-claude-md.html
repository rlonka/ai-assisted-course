B3 Týden 2 Blok B: Agentní paradigma

Memory a CLAUDE.md

Jak dát agentovi trvalou paměť projektu — co psát, co ne, a jak se liší tři typy paměti v Claude Code

1 — Jádro

Agent nemá paměť mezi sezeními — pokud mu ji nedáš. Každá nová session začíná od nuly: prázdný kontext, žádná znalost tvého projektu, žádné konvence. CLAUDE.md tento problém řeší: je to soubor, který Claude Code přečte automaticky na začátku každé session a přidá do kontextu. Není to prompt — je to konfigurace projektu pro agenta.

Správně napsaný CLAUDE.md znamená: agent ví, jak projekt vypadá, jaký má styl, co jsou jeho invarianty, a jaký jazyk domény tým používá — bez toho, abys to musel vysvětlovat pokaždé znovu.

Jedno pravidlo

Cokoliv, co jsi napsal do promptu více než jednou, patří do CLAUDE.md. Cokoliv, co agent potřebuje vědět o projektu — ne o úkolu — patří do CLAUDE.md.

2 — Tři typy paměti v Claude Code

Claude Code rozlišuje tři různé mechanismy paměti. Jsou navzájem nezávislé, řeší různé problémy, a nesměšují se.

Soubor / mechanismus Kdo píše Kdy se čte Co patří dovnitř
CLAUDE.md Ty (ručně) Každá session automaticky Konvence projektu, ubiquitous language, invarianty, tech stack
.claude/memory/ Agent (automaticky) Na žádost, nebo když je relevantní Dočasné poznámky, co si agent zapamatoval napříč sezeními
.claude/settings.json Ty (ručně nebo přes /config) Při startu Claude Code Konfigurace nástrojů, povolení, hooky — ne instrukce pro model
Nejčastější záměna

settings.json není paměť pro agenta — je to konfigurace harness. .claude/memory/ není pro tebe — je to zápisník agenta. Ty píšeš do CLAUDE.md; agent si píše do memory/; systém si čte ze settings.json.

3 — Hierarchie CLAUDE.md souborů

CLAUDE.md existuje ve třech vrstvách. Claude Code je načte všechny a sloučí do kontextu — přičemž specifičtější soubor má přednost.

🌍 ~/.claude/CLAUDE.md Globální — platí pro všechny projekty
↓ přidá se k
📁 ./CLAUDE.md Projektový — v kořeni repozitáře
↓ přidá se k
📄 ./.claude/CLAUDE.md Lokální — přepsání pro konkrétní kontext

Globální CLAUDE.md je místo pro preference, které chceš ve všech projektech — tvůj preferovaný styl odpovědí, jazyk (česky / anglicky), co agent nikdy nesmí dělat bez potvrzení. Projektový CLAUDE.md je pro znalost konkrétního projektu — a měl by být součástí repozitáře, verze-kontrolovaný, sdílený s týmem.

4 — Co patří do CLAUDE.md (a co ne)

Patří dovnitř ✓

  • Tech stack a verze ("Python 3.12, pytest, numpy")
  • Ubiquitous language domény ("simulation step = jeden časový krok fyziky")
  • Konvence pojmenování ("proměnné v snake_case, třídy PascalCase")
  • Testovací strategie ("unit testy v tests/, integrační v tests/integration/")
  • Invarianty a omezení ("výstupní pole musí mít dtype float64")
  • Struktura projektu ("src/ je zdrojový kód, data/ nikdy necommituj")
  • Workflow pravidla ("commituj jen zelené testy")

Nepatří dovnitř ✗

  • Přihlašovací údaje, tokeny, secrets
  • Dočasný stav ("teď pracuji na feature X")
  • Debugging poznámky ("bug byl v řádku 42")
  • Instrukce pro konkrétní úkol (to patří do promptu)
  • Obsah, který je v kódu — agent kód přečte sám
  • Celý README — shrň, nevkopíruj

Pravidlo: CLAUDE.md popisuje jak projekt funguje, ne co chceš udělat dnes. Pokud záznam zastarává rychleji než jednou za měsíc, nepatří tam.

5 — Jak psát záznamy: technika

Špatný záznam v CLAUDE.md je delší než jeden tweet a popisuje proč, ne co. Dobrý záznam je deklarativní, konkrétní, a bez vysvětlování.

# Špatně — příliš obecné, bez akčního obsahu Tento projekt používá Python a numpy. Měli jsme problémy s výkonem, proto jsme přešli na vektorizované operace. Kód by měl být čitelný. # Dobře — konkrétní, deklarativní, actionable ## Stack - Python 3.12, numpy 2.0, pytest 8.x - Výstupy: HDF5 (h5py), nikdy CSV pro výsledky > 1 MB ## Konvence - Pole: vždy dtype=float64, shape (N, 3) pro 3D vektory - Testy: jeden test = jeden fyzikální invariant - Žádné pandas v src/ — jen v notebooks/ ## Ubiquitous language - "particle" = jeden simulovaný objekt (ne "object", ne "agent") - "step" = jeden časový krok dt, ne iterace smyčky - "ensemble" = kolekce nezávislých simulation runs

Záznamy jsou krátké proto, že agent celý soubor načte do kontextu. Čím kratší a konkrétnější, tím spolehlivěji instrukce platí. Vágní instrukce ("kód by měl být čitelný") agent interpretuje — konkrétní instrukce ("žádné pandas v src/") platí vždy.

6 — Co je .claude/memory/ a k čemu slouží

Claude Code si může sám psát poznámky do .claude/memory/ — to jsou soubory, které agent vytváří při sezeních, pokud ho instruuješ, aby si něco zapamatoval (nebo pokud má auto-memory zapnutou). Tyto soubory nejsi ty — jsou to agentovy zápisky.

Rozdíl v praxi:

  • CLAUDE.md — ty píšeš: "Tento projekt nikdy nepoužívá globální proměnné." Agent to přečte každou session.
  • .claude/memory/ — agent si napíše: "Uživatel preferuje stručné odpovědi bez bulleted lists." Agent si to přečte, když to potřebuje.
Praktické rozlišení

Pokud chceš, aby instrukce platila vždy a přesně tak, jak jsi ji napsal → CLAUDE.md. Pokud chceš, aby si agent postupně akumuloval znalost o tobě → dovol mu psát do memory/. Obojí pracuje vedle sebe; nemíchej je.

7 — Tři příklady

Vědec-kodér

Fyzikální simulace. CLAUDE.md obsahuje tři záznamy: fyzikální jednotky (SI, žádné CGS), invarianty výstupu (energie se musí konzervovat v mezích 1e-6), a pojmy domény (particle, ensemble, timestep). Bez těchto záznamů agent navrhuje kód, který simulaci "funguje" ale porušuje fyzikální konzistenci. S nimi: první návrh splňuje invarianty.

RSE vývojář

Větší tým, Python + Rust backend. CLAUDE.md je verze-kontrolovaný, commitovaný do repozitáře, každý vývojář ho má. Obsahuje: ADR (architecture decision records) v jedné větě každý, API konvence, jak se navrhuje CI. Výsledek: každý člen týmu dostane ze stejného promptu výsledek v souladu s architekturou — ne podle toho, co si agent "myslí" je standard.

Manažer / PI

Tým nasadil Claude Code, ale každý vývojář má vlastní CLAUDE.md (nebo žádný). Po třech měsících: kód je inkonzistentní, code review trvá dvakrát déle než dřív, protože agent navrhl každému jiný styl. Sdílený projektový CLAUDE.md je tedy technická infrastruktura, ne osobní preference — stejně jako sdílený linter konfigurační soubor.

8 — Propojení na ostatní lekce

  • B2 — Rámec pěti otázek: Memory je vrstva 1 — základ, na kterém stojí Skills, Hooks, MCP a Subagents. Bez CLAUDE.md jsou ostatní vrstvy nepředvídatelné, protože agent pracuje s jiným implicitním kontextem.
  • A4 — Domain-Driven Design: Ubiquitous Language z DDD (Evans, 2003) jde přímo do CLAUDE.md. Pojmy domény, které tým sdílí, jsou přesně to, co agent potřebuje znát natrvalo. CLAUDE.md je glossary projektu.
  • B1 — Harness vs. Guardrails: CLAUDE.md je hlavní harness komponent — pozitivní architektura. Dáváš agentovi znalost projektu. Guardrails (hooks) jsou negativní architektura — definuješ, co nesmí. Obojí spolupracuje.
  • A1 — TDD: Testovací konvence patří do CLAUDE.md. "Jeden test = jeden invariant", "testy v tests/unit/", "fixtures v conftest.py" — agent pak generuje testy v souladu s projektem, ne podle defaultů.

9 — Nejčastější nepochopení

Nepochopení 1

"CLAUDE.md je jako README — napíšu ho jednou a pak ho nebudu měnit."

Skutečnost

CLAUDE.md je živý dokument. Přidáváš záznamy, když zjistíš, že opakuješ stejný prompt. Odstraňuješ záznamy, které zastaraly. Dobré pravidlo: po každých deseti sezeních projdi CLAUDE.md a odstraň, co je nepravdivé nebo co agent ignoruje.

Nepochopení 2

"Čím víc toho napíšu do CLAUDE.md, tím lépe agent rozumí projektu."

Skutečnost

Příliš dlouhý CLAUDE.md má opačný efekt: agent diluje pozornost po celém dokumentu a důležité instrukce ztratí váhu. Pravidlo palce: CLAUDE.md by měl být čitelný za pět minut. Pokud je delší, rozděl ho tematicky nebo odstraň, co není akcidentálně specifické pro projekt.

Nepochopení 3

"Agent instrukce v CLAUDE.md vždy uposlechne."

Skutečnost

CLAUDE.md prochází modelem — model ho interpretuje, ne vykonává mechanicky. Vágní instrukce ("buď opatrný") agent ignoruje nebo interpretuje libovolně. Konkrétní, kontrolovatelné instrukce ("žádný přímý commit do main") fungují lépe. Pro kritické invarianty použij hook (guardrail) — ne CLAUDE.md.

10 — Spicy teze

CLAUDE.md není soubor pro agenta. Je to sdílená specifikace projektu — stejně jako architektonické rozhodnutí nebo testovací strategie. Tým bez sdíleného CLAUDE.md nemá AI problém. Má disciplinární problém: neví, co je norma projektu, a agent jim to přesně zrcadlí.

11 — Primární zdroje

  • Claude Code — Memory (CLAUDE.md) Proč: Oficiální dokumentace. Přečti celou stránku (10 min) — obsahuje přesná pravidla pro hierarchii souborů, co se načítá automaticky a co ne, a jak funguje auto-memory. Základní zdroj pro tuto lekci.
  • Domain-Driven Design — Eric Evans (2003), kap. 1–2 Proč: Ubiquitous Language (kap. 2) je historická kotva pro CLAUDE.md. Evans psal pro tým sdílející jazyk domény — CLAUDE.md je tentýž princip aplikovaný na agenta. Kap. 2 je 20 stran; stačí první polovina.
  • Claude Code — Settings & Permissions Proč: Pochopíš, co patří do settings.json a co do CLAUDE.md — jsou to různé věci pro různé vrstvy systému. Přečti sekci "Project settings" a "Permissions".

12 — Feynmanovo cvičení

Feynmanův test — Memory a CLAUDE.md
1. Výzkumník napsal do CLAUDE.md: "Teď pracuji na refaktoringu parseru — zatím nerušit." Za tři týdny se diví, proč agent odmítá pracovat na jiných věcech. Jaká je příčina?
2. Tým má CLAUDE.md verze-kontrolovaný v repozitáři. Nový člen chce přidat osobní preference (preferuje krátké odpovědi). Kam je správně uložit?
3. Agent konzistentně ignoruje instrukci "nikdy necommituj přímo do main". Navrhni správné řešení.
4. Proč je "ubiquitous language" z DDD přímou analogií k obsahu CLAUDE.md?

13 — Co dál

Co musíš znát před touto lekcí:

  • B2 — Rámec pěti otázek — Memory je vrstva 1. Tato lekce ji rozvíjí do detailu.
  • B1 — Harness vs. Guardrails — CLAUDE.md je harness; pro kritické invarianty je potřeba guardrail (hook).

Praktický úkol (20 minut): Vezmi libovolný projekt, na kterém teď pracuješ. Napiš minimální CLAUDE.md — tech stack (2–3 řádky), tři pojmy ubiquitous language, dva konvencí invarianty. Otevři Claude Code a dej agentovi úkol, který normálně vyžaduje kontext projektu. Porovnej výsledek s výsledkem bez CLAUDE.md.

Příští lekce:

  • B4 — Skills a slash commands — vrstva 2 rámce pěti otázek. Jak enkapsulovat opakované workflows jako /skill-name, kdy skill postavit a kdy si vystačit s promptem.

Propojení do curricula:

  • A4 — Domain-Driven Design — celá lekce o ubiquitous language a bounded contexts. Ubiquitous language z A4 jde přímo do CLAUDE.md sekce "Pojmy domény".
  • C3 — Deskilling — špatný CLAUDE.md agenta naučí špatným vzorům. Pokud agent postupně přebírá rozhodnutí, která patří tobě, může to být signál, že CLAUDE.md mu dává příliš volnou ruku.
