B4 Týden 3 Blok B: Agentní paradigma

Skills a slash commands

Jak zabalit opakovaný workflow do pojmenovaného /příkazu — kdy skill postavit, kdy si vystačit s promptem, a proč je to refaktoring, ne magie

1 — Jádro

Když se přistihneš, že píšeš agentovi potřetí tentýž mnohakrokový prompt — "spusť testy, když spadnou, oprav je, pak zaformátuj, pak commitni" — právě jsi našel kandidáta na skill. Skill je opakovaný workflow zabalený do pojmenované, znovupoužitelné jednotky, kterou vyvoláš jako /skill-name.

Skill není nová schopnost agenta. Je to abstrakce postupu, který už umíš popsat. Stejně jako v programování extrahuješ opakovaný blok kódu do funkce, tady extrahuješ opakovaný prompt do skillu. Vrstva 2 rámce pěti otázek zní přesně takto: "Které opakované workflows jsou enkapsulované?"

Jedno pravidlo

Skill vyřeš, když prompt opakuješ. Ne dřív. Skill je refaktoring workflow — a refaktoring bez duplicity je předčasná abstrakce.

2 — Skill vs. prompt vs. CLAUDE.md vs. hook

Skill se snadno zamění s ostatními mechanismy. Rozdíl je v tom, kdo ho spouští a kdy se aktivuje.

Mechanismus Kdo spouští Kdy se aktivuje Na co je
Prompt Ty, ručně Jednorázově, teď Unikátní úkol, který se nebude opakovat
CLAUDE.md Systém Vždy, pasivně v pozadí Znalost projektu, kterou agent má mít pořád
Skill Ty, přes /název Na vyžádání, aktivně Opakovaný postup — sekvence kroků
Hook Harness Automaticky, deterministicky Guardrail — co se musí (ne)stát vždy
Nejčastější záměna

CLAUDE.md je znalost, skill je postup. "Projekt používá pytest" → CLAUDE.md. "Spusť pytest, přečti selhání, oprav, opakuj až zelená" → skill. Skill je harness (vyvoláš ho ty), hook je guardrail (spustí se sám). Když chceš, aby se něco stalo vždy bez tvého zásahu, není to skill — je to hook.

3 — Anatomie skillu

Skill v Claude Code je adresář se souborem SKILL.md: frontmatter (jméno + popis) a tělo s instrukcemi. Volitelně přibalí skripty nebo referenční soubory. Popis (description) je klíčový — podle něj agent (a ty přes /) skill najde.

# .claude/skills/run-tests/SKILL.md --- name: run-tests description: Spustí pytest, přečte selhání, opraví je a opakuje, dokud nejsou všechny testy zelené. --- # Postup 1. Spusť `pytest -q`. 2. Pokud vše projde, skonči a nahlas výsledek. 3. Pokud něco spadne, přečti traceback — oprav *příčinu*, ne symptom. Neupravuj test, jen aby prošel. 4. Znovu spusť pytest. Opakuj od kroku 2. 5. Nikdy necommituj — jen dosáhni zelené.

Vyvoláš ho napsáním /run-tests. Agent načte SKILL.md až v tu chvíli — do té doby zabírá v kontextu jen jeden řádek (jméno + popis). To je progressive disclosure a je to důvod, proč můžeš mít desítky skillů, aniž bys zahltil kontext.

4 — Kdy postavit skill (a kdy ne)

Postav skill ✓

  • Tentýž mnohakrokový prompt jsi napsal 3× (pravidlo tří)
  • Postup má jasné, opakovatelné kroky
  • Chceš ho sdílet s týmem (skill jde do repozitáře)
  • Workflow má správné pořadí, na kterém záleží
  • Chceš konzistentní výsledek napříč lidmi a sezeními

Nech to promptem ✗

  • Úkol je jednorázový, nebude se opakovat
  • Postup je pokaždé jiný
  • Je to jen znalost projektu → patří do CLAUDE.md
  • Musí se to stát vždy a automaticky → patří do hooku
  • Skill by měl jeden řádek ("naformátuj kód") — to je prompt

Pravidlo tří je totéž, co v refaktoringu: první výskyt napíšeš, druhý zaskřípeš, třetí extrahuješ. Skill dřív než potřetí je předčasná abstrakce — investuješ do údržby něčeho, o čem ještě nevíš, jestli má stabilní tvar.

1× Napíšeš prompt. Funguje. Zapomeneš na něj.
2× Píšeš skoro totéž. Zaskřípeš — ale ještě neabstrahuj.
3× Potřetí. Teď víš, že tvar je stabilní → extrahuj skill.

5 — Proč skills škálují: progressive disclosure

Naivní obava: "Když budu mít dvacet skillů, zahltím kontext dvaceti postupy." Nezahltíš. Do kontextu se na začátku načte jen jméno a popis každého skillu — jeden řádek. Tělo skillu (celý postup, skripty, reference) se načte, až když ho vyvoláš.

To má dva důsledky, na kterých záleží:

  • Popis je rozhraní. Agent se rozhoduje, jestli je skill relevantní, výhradně podle description. Vágní popis = skill se nikdy nenajde. Popis piš tak, aby z něj bylo jasné kdy skill použít, ne jen co dělá.
  • Skillů může být hodně. Protože každý stojí v základu jen řádek, můžeš mít knihovnu skillů pro celý projekt. Náklad na kontext je lineární v počtu skillů, ne v jejich velikosti.
Praktický důsledek

Investuj čas do description, ne jen do těla skillu. Tělo přečte agent, až když skill vyvolá — ale jestli ho vůbec vyvolá, rozhoduje popis. Špatný popis = mrtvý skill, který nikdo (ani agent) nenajde.

6 — Historický kontext

Skills nejsou nový nápad. Jsou to staré principy inženýrství aplikované na workflow s agentem:

  • DRY (Don't Repeat Yourself), Hunt & Thomas 1999. Každý kus znalosti má mít jedinou reprezentaci. Opakovaný prompt porušuje DRY — skill ho obnovuje.
  • Extract Method, refaktoring (Fowler). Skill je Extract Method aplikovaný na prompt. Duplicitní sekvence kroků → pojmenovaná, znovupoužitelná jednotka.
  • Collective ownership, XP. Skill commitnutý do repozitáře je sdílený tým­ový nástroj — každý ho vyvolá stejně, každý dostane stejný postup.
  • Unix philosophy. Malé, složitelné nástroje s jasným jménem. /skill je moderní obdoba shell aliasu nebo Makefile targetu.

To je dobrá zpráva pro publikum: nemusíš se učit nový mentální model. Skill = funkce pro workflow. Kdy extrahovat funkci, už víš.

7 — Tři příklady

Vědec-kodér

Po každé změně v simulaci opakuje tentýž rituál: spustit benchmark, porovnat s baseline, zkontrolovat, že energie se konzervuje. Třikrát to napsal jako prompt. Teď má /verify-run — jeden skill, tři kroky. Vyvolá ho po každé změně a dostane stejnou kontrolu pokaždé. Přestal zapomínat na krok s konzervací energie, protože ho už nedělá z hlavy.

RSE vývojář

Tým má release proces: changelog, bump verze, tag, build wheel, smoke test. Dřív to každý dělal trochu jinak. Teď je to /release commitnutý v repozitáři. Skill je verze-kontrolovaný — když se proces změní, změní se skill v PR a projde review. Onboarding nového člena: "spusť /release", ne třístránkový wiki dokument, který nikdo nečte.

Manažer / PI

Vidí, že dva seniorní vývojáři odcházejí a odchází s nimi "jak se to tady dělá". Skills jsou způsob, jak tacit knowledge udělat explicitní a přenositelnou: postup, který byl dřív v hlavě, je teď SKILL.md v repozitáři. Není to náklad navíc — je to pojistka proti bus factoru. Skills jsou institucionální paměť týmu, ne osobní zkratka.

8 — Propojení na ostatní lekce

  • B2 — Rámec pěti otázek: Skills jsou vrstva 2 — enkapsulované workflows. Stojí na vrstvě 1 (Memory): skill předpokládá znalost projektu z CLAUDE.md a staví na ní postup.
  • B3 — Memory a CLAUDE.md: Ostrá hranice. CLAUDE.md je znalost ("používáme pytest"), skill je postup ("spusť pytest a oprav selhání"). Když nevíš, kam co dát, zeptej se: je to fakt o projektu, nebo sekvence akcí?
  • B5 — Hooks: Skill vyvoláš ty (harness); hook se spustí sám (guardrail). "Chci to spouštět, když se rozhodnu" → skill. "Musí se to stát vždy" → hook. Stejný postup může být skill i hook — liší se, kdo drží spoušť.
  • A2 — Refactoring: Pravidlo tří a Extract Method jsou přímo z refaktoringu. Skill je refaktoring aplikovaný na prompt místo na kód. Stejná disciplína, stejné signály duplicity.

9 — Nejčastější nepochopení

Nepochopení 1

"Čím víc skillů mám, tím lepší je moje AI setup."

Skutečnost

Počet skillů není metrika kvality. Skill, který jsi vyvolal jednou, je náklad na údržbu bez návratnosti — zastará, přestane platit, a matoucí popis znečistí kontext. Dobrý setup má málo skillů, které se používají často. Skill bez opakování je předčasná abstrakce.

Nepochopení 2

"Skill je chytřejší než prompt — dá agentovi schopnost, kterou jinak nemá."

Skutečnost

Skill nepřidává schopnost. Je to tentýž prompt, jen pojmenovaný a znovupoužitelný. Když postup nefunguje jako prompt, nebude fungovat ani jako skill. Skill řeší opakování, ne schopnost. Nejdřív ověř, že postup funguje jako prompt — pak ho teprve extrahuj.

Nepochopení 3

"Všechno, co dělám opakovaně, patří do skillu."

Skutečnost

Opakovaná znalost patří do CLAUDE.md. Opakovaný guardrail patří do hooku. Do skillu patří opakovaný postup, který vyvoláváš ty. Otázka není "opakuje se to?", ale "je to postup, sekvence akcí, kterou chci spouštět na povel?"

10 — Spicy teze

Skills nejsou o AI. Jsou o tom, že většina týmů nikdy nezapsala, jak vlastně dělají svou práci. Agent jen zviditelnil díru, která tam byla pořád: postupy žijí v hlavách, ne v repozitáři. Kdo neumí popsat svůj workflow do SKILL.md, neměl ho pod kontrolou ani předtím — jen to nebylo vidět.

13 — Až se tě zeptají 🎤

Ostré dotazy z publika + krátká odpověď s pointou (tučně). Trénuj nahlas, ne čtením.

Námitka „víc skillů": „Čím víc skillů mám, tím lepší je můj AI setup, ne?"

Ne — počet skillů není metrika kvality. Skill vyvolaný jednou je náklad na údržbu bez návratnosti (zastará, matoucí popis znečistí kontext). Dobrý setup má málo skillů, které se používají často.

Chyták „chytřejší": „Skill je chytřejší než prompt — dá agentovi schopnost navíc."

Ne. Skill nepřidává schopnost — je to tentýž prompt, jen pojmenovaný a znovupoužitelný. Když postup nefunguje jako prompt, nebude ani jako skill. Skill řeší opakování, ne schopnost.

Námitka „všechno do skillu": „Všechno, co dělám opakovaně, patří do skillu."

Ne. Opakovaná znalost → CLAUDE.md, opakovaný guardrail → hook, opakovaný postup na povel → skill. Otázka není „opakuje se to?", ale „je to sekvence akcí, kterou chci spouštět na povel?"

Obava „zahlcení": „Když budu mít dvacet skillů, nezahltím kontext?"

Ne. Do kontextu jde jen jméno + popis (řádek), tělo až při vyvolání — to je progressive disclosure. Náklad je lineární v počtu skillů, ne v jejich velikosti. Klidně měj knihovnu skillů.

Problém „nikdo ho nepoužívá": „Postavil jsem skill, ale agent ho nevyvolává — proč?"

Nejspíš vágní description. Agent se rozhoduje výhradně podle popisu. Popis piš tak, aby bylo jasné, KDY skill použít, ne jen co dělá. Špatný popis = mrtvý skill, který nikdo (ani agent) nenajde.

Otázka „kdy": „Kdy je správný čas skill postavit?"

Pravidlo tří: potřetí, co píšeš skoro tentýž mnohakrokový prompt. Postup má jasné opakovatelné kroky, chceš ho sdílet a konzistentní napříč lidmi. Dřív než potřetí = předčasná abstrakce.

16 — Co dál

Co musíš znát před touto lekcí:

  • B2 — Rámec pěti otázek — Skills jsou vrstva 2. Tato lekce ji rozvíjí do detailu.
  • B3 — Memory a CLAUDE.md — hranice znalost (CLAUDE.md) vs. postup (skill) je jádro této lekce.

Praktický úkol (20 minut): Projdi svou historii promptů za poslední týden. Najdi jeden mnohakrokový postup, který jsi napsal aspoň třikrát. Napiš z něj minimální SKILL.md — jméno, jeden dobrý popis (kdy ho použít), a kroky postupu. Vyvolej ho přes /název a porovnej s ručním promptem. Pak si zkus jeden postup, který jsi napsal jen jednou — a zdůvodni si, proč z něj skill neděláš.

Příští lekce:

  • B5 — Hooks — vrstva 3 rámce pěti otázek. Deterministické guardrails: co se musí (ne)stát vždy, bez ohledu na to, co agent chce. Skill vyvoláš ty; hook se spustí sám. Tady se ta hranice ostře vyostří.

Propojení do curricula:

  • A2 — Refactoring — pravidlo tří a Extract Method jsou přímo odtud. Skill je refaktoring workflow místo kódu.
  • C3 — Deskilling — pozor: skill, který zabalí rozhodování (ne jen mechaniku), může postupně převzít úsudek, který má zůstat tvůj. Skill má automatizovat rutinu, ne myšlení.
