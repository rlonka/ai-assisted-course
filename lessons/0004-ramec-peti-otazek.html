B2 Týden 2 Blok B: Agentní paradigma

Rámec pěti otázek

Memory, Skills, Hooks, MCP, Subagents — inventory, který rozhoduje, jestli agent pracuje pro tebe, nebo ty pro agenta

1 — Jádro

Před každým netriviálním úkolem polož pět otázek. Každá otázka ověřuje jednu vrstvu agentovního workflow — a každá vrstva řeší jiný typ selhání. Pokud přeskočíš vrstvu, agent to nezahlásí. Odneseš si výsledek, který vypadá správně, ale stojí na hádání.

1 Memory Co agent ví natrvalo? CLAUDE.md, memory/ B3
2 Skills Které workflows jsou jako slash commands? B4
3 Hooks Co se spustí deterministicky — bez ohledu na agenta? B5
4 MCP Ke kterým externím nástrojům má agent přístup? B6
5 Subagents Kdy rozbít práci na více agentů? B9
Proč tento rámec existuje

Agent je dobrý přesně tak, jak dobrý je kontext, který dostane. Rámec pěti otázek je systematický způsob, jak tento kontext budovat — ne ad hoc, ne z paměti, ale jako disciplína před každým úkolem.

3 — Historický kontext

Každá z pěti otázek má kořeny v klasické softwarové disciplíně. Nejsou to nové nápady — jsou to staré disciplíny přeložené do agentního kontextu.

  • Memory → Ubiquitous Language (Evans, DDD 2003). Celý tým mluví stejným jazykem domény. CLAUDE.md je glossary projektu — agent se naučí termíny, konvence a invarianty projektu jednou, ne při každém promptu.
  • Skills → XP collective ownership + refactoring. Opakovaný pattern je kandidát na abstrakci. Skill je procedurální abstrakce nad agentovým workflow — stejná myšlenka jako funkce.
  • Hooks → CI/CD tradice (Jenkins, GitHub Actions). Deterministická gate na každý commit. Hook je guardrail (B1) — spustí se vždy, agent ho nemůže přeskočit.
  • MCP → Unix filozofie. "Do one thing well." MCP server je specializovaný nástroj s jasným API. Agent orchestruje — nástroje provádějí.
  • Subagents → Distributed systems. Izolace státu, message passing, specializace. Agent je proces. Workflow je orchestrátor. Kontext se nedělí — předává.
Propojení s Brooksem (A3)

Rámec pěti otázek je systematická odpověď na akcidentální komplexitu agentního workflow. Memory, Skills, Hooks — to jsou nástroje, jak snížit kognitivní overhead spolupráce s agentem. Esenciální problém (co chceš) zůstává na tobě; pět otázek řeší, jak ho efektivně předat.

4 — Audit v praxi

Rámec funguje jako checklist. Než zadáš agentovi netriviální úkol, projdi pět otázek v pořadí — každá stojí na předchozí.

Audit — příklad výstupu

Projekt: vědecká simulace, Python, pytest.
1. Memory ✓ — CLAUDE.md existuje: numpy konvence, výstupní formát HDF5, styl komentářů.
2. Skills △ — chybí skill pro spuštění benchmarku. Opakuji tentýž prompt.
3. Hooks ✓ — hook na pytest, agent nemůže commitovat bez zelených testů.
4. MCP ✗ — agent nemá přístup k výsledkům CI. Ptám se ho na věci, které si musím zjistit sám.
5. Subagents △ — pro review kódu spouštím jednoho agenta. Mohl bych paralelizovat.
Výsledek: nastavit MCP pro CI, přidat benchmark skill.

Nemusíš mít všech pět vrstev najednou. Začni s Memory — je to minimum. Přidávej vrstvy, když narazíš na opakující se problém.

5 — Tři příklady

Vědec-kodér

Nastavíš CLAUDE.md s popisem datového formátu, numpy konvencemi, fyzikálními jednotkami. Přidáš hook na pytest. Agent přestane navrhovat pandas tam, kde je numpy standard — a nepustí commit bez testů. Dvě vrstvy stačí na začátek.

RSE vývojář

Plný stack: CLAUDE.md s architekturou a ADR (architecture decision records), skills pro review a deployment, hooks na testy + linting + type checking, MCP servery pro CI a databázi, subagents pro paralelní review bezpečnosti vs. správnosti. Výsledek: prediktabilní chování agenta — ne náhoda.

Manažer / PI

Tým nasadil AI, velocity vzrostla 30 %. Za tři měsíce: každý vývojář má jiný výsledek ze stejného promptu. Příčina: chybí Memory vrstva. Žádný sdílený CLAUDE.md → žádný sdílený kontext → nepředvídatelné výstupy. CLAUDE.md není pro agenta — je to shared specification pro celý tým.

6 — Propojení na ostatní lekce

  • B1 — Harness vs. Guardrails: Hooks jsou guardrails. Skills jsou harness. Rámec pěti otázek pojmenovává, kam každý z nich patří v celkovém inventáři.
  • A1 — TDD: Selhávající test je harness (Skills + Hooks). Hook blokuje commit bez testů. Memory obsahuje testovací konvence. Všechny tři vrstvy spolupracují na TDD workflow.
  • A4 — DDD: Ubiquitous language z DDD jde přímo do Memory (CLAUDE.md). Pojmy domény jsou přesně to, co agent potřebuje znát natrvalo.
  • B3–B6 — Deepdive: Každá z prvních čtyř vrstev má vlastní lekci. Tato lekce je mapa; jednotlivé lekce jsou territory.

7 — Nejčastější nepochopení

Co si lidé myslí

"Stačí dobrý prompt. CLAUDE.md je overhead — radši ten čas věnuji samotnému úkolu."

Skutečnost

Dobrý prompt řeší jednu session. CLAUDE.md řeší všechny session. Čas na nastavení CLAUDE.md se vrátí ve druhé session — a v každé další. Prompt je jednorázový; Memory je investice.

Druhé nepochopení

"MCP je zbytečná komplexita pro můj projekt."

Skutečnost

Bez MCP si agent musí buď domyslet stav externího systému (hádá), nebo ho dostane přes copy-paste (chybí kontext). MCP není komplexita navíc — je to standardizovaná náhrada za chaotický copy-paste. Otázka není "je MCP nutné", ale "kolik copy-paste toleruješ."

8 — Spicy teze

Prompt bez rámce pěti otázek je jako test bez specifikace — výsledek závisí na tom, co AI odhadne. Rámec pěti otázek je tvoje specifikace pro agenta. Kdo ji nepíše, neprogramuje agenta — jen doufá.

9 — Primární zdroje

  • Claude Code — Memory (CLAUDE.md) Proč: Oficiální dokumentace Memory vrstvy. Přečti celou stránku — je krátká a obsahuje přesná pravidla pro CLAUDE.md vs. memory/ vs. .claude/settings.json.
  • Claude Code — Hooks Proč: Hooks jsou deterministická vrstva guardrails. Dokumentace obsahuje příklady před/po akcích agenta. Spolu s Memory jsou to dvě nejdůležitější vrstvy pro stabilní workflow.
  • MCP — Introduction (modelcontextprotocol.io) Proč: Kratší verze MCP specifikace. Přečti "Introduction" a "Concepts" — zbytek je implementační detail. Klíčové: Resources, Tools, Prompts jako tři typy MCP capabilities.
  • Domain-Driven Design — Eric Evans (2003), kap. 1–2 Proč: Ubiquitous Language je historická kotva pro Memory vrstvu. Kap. 1 (30 stran) je maximum, co potřebuješ. Argument pro sdílený jazyk domény platí dnes pro agenta stejně jako tehdy pro tým.
