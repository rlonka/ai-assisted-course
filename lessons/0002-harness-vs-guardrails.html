B1 Týden 1 Blok B: Agentní paradigma

Harness vs. Guardrails

Architektura systému kolem modelu — co dává agentovi schopnosti a co ho drží v mezích

1 — Jádro

Model samotný neumí nic specifického. To, co ho dělá užitečným pro konkrétní práci, je harness — veškerý kontext, nástroje a konfigurace, které ho obklopují. To, co ho drží od nebezpečného jednání, jsou guardrails — deterministické zábrany, které neprojdou přes model vůbec. Harness je pozitivní architektura: přidáváš, co agent potřebuje umět. Guardrails jsou negativní architektura: definuješ, co nesmí. V Claude Code jsou obojí explicitní a programovatelné — ne přednastavené a skryté.

Proč to musíš umět přednášet

Většina lidí si myslí, že AI nástroj je jen "model + API". Harness/guardrails ti dá jazyk pro rozhovor o tom, jak se AI integruje do vědeckého workflow — co tým musí nakonfigurovat, kde jsou rizika, kde je odpovědnost.

Slovníček — dvě anglická slova, která musíš přeložit publiku

„Harness" a „guardrails" jsou v Claude Code zažité anglické termíny, ale české vědecké publikum potřebuje obraz. Obojí jsou věci, které ty stavíš kolem modelu — ne něco, co je uvnitř něj.

harness = postroj / rám (co agent UMÍ)
  • Vše, co modelu přidáš, aby uměl tvou konkrétní práci: kontext (CLAUDE.md), nástroje, skills, MCP, paměť
  • Pozitivní architektura — přidáváš schopnosti
  • Obraz: koňský postroj — teprve s ním kůň utáhne tvůj vůz. Sám model je jen ten kůň.
guardrails = svodidla / mantinely (co agent NESMÍ)
  • Deterministické zábrany mimo model, které ho nepustí do nebezpečné akce: hooks (exit 2), permission system
  • Negativní architektura — zakazuješ akce
  • Obraz: svodidla na silnici — nezrychlí tě, ale nepustí tě ze srázu.
⚠️ Dva chytáky

(1) Harness ≠ prompt. Prompt je jednorázová věta; harness je celé trvalé prostředí kolem modelu (paměť, nástroje, konfigurace), které platí napříč sezeními.
(2) Guardrails nejsou „to, co nastavil Anthropic". Lokální guardrails píšeš ty jako shell skripty v settings.json — jsou pod tvou kontrolou. (Víc v sekci 6.)

2 — Historický kontext

Koncept není nový. Harness = prostředí, ve kterém agent operuje. Guardrails = omezení jeho autonomie. Analogie:

  • Unix shell (1969): shell je harness (dává programům I/O, proměnné, pipes), file permissions jsou guardrails.
  • Kubernetes (2014): pod je harness (CPU, memory, volumes, env vars), RBAC a network policies jsou guardrails.
  • Claude Code (2025): CLAUDE.md, MCP servery, skills, nástroje = harness. Hooks s exit code 2, permission system = guardrails.

Vzor je starý. Co je nové: model v centru je nepředvídatelnější než program. Proto jsou guardrails důležitější než dřív — a harness je složitější než dřív, protože kontext rozhoduje víc než API.

3 — Jak to funguje v Claude Code

Každý request projde touto sekvencí:

Uživatel Prompt, příkaz, nebo trigger z hooku
↓
Harness CLAUDE.md načten → memory → skills aktivní → MCP servery připojeny → nástroje definovány
↓
Model Reasonuje, generuje akce (tool calls, text)
↓
Guardrails Hooks zkontrolují akci před spuštěním — exit code 2 = blokace, permission system = allowlist/blocklist
↓
Akce Soubor upraven, příkaz spuštěn, výsledek vrácen modelu

Klíčový detail: guardrails běží mimo model. Shell hook spustíš v Bashi — neprochází přes LLM inference. To znamená, že jsou spolehlivé i když model halucinuje.

4 — Tři příklady

Vědec-kodér

Harness: CLAUDE.md obsahuje, jaký numerický solver projekt používá, jaká je konvence pojmenování proměnných, kde jsou testovací data. Agent bez toho generuje generický Python.
Guardrail: Hook blokuje jakýkoliv git push bez manuálního potvrzení. Produkční výsledky nemůže agent pushovat sám.

RSE vývojář

Harness: MCP server zpřístupňuje agentovi dokumentaci HPC clusteru a job scheduling API. Agent může navrhovat SLURM skripty správně pro konkrétní systém.
Guardrail: Permission system: Bash nástroj povolen jen pro read-only příkazy (grep, ls, cat). Spouštění jobů prochází schválením.

Manažer / PI

Tým řekne: "Nasadili jsme AI, ale nedělá nic specifického pro náš projekt." Příčina: harness je prázdný — agent nemá kontext domény. Guardrails možná fungují (agent nic nerozbíjí), ale harness je slabý, takže výstup je generický a zbytečný.

5 — Propojení na rámec pěti otázek

Harness a guardrails jsou architekturální meta-koncepty. Pět otázek (lekce B2) je jejich inventář:

  • Memory (CLAUDE.md) — hlavní harness komponent. Dává modelu esenciální znalost projektu.
  • Skills — harness + guardrail hybrid. Skill definuje jak má agent přistoupit k úkolu (harness), a tím zároveň omezuje, co neudělá (soft guardrail).
  • Hooks — čistý guardrail. Deterministické, mimo model, exit code 2 = tvrdá blokace.
  • MCP — harness rozšíření. Přidává agentovi nástroje (databáze, API, filesystem) bez nutnosti je psát do promptu.
  • Subagents — harness vzor. Orchestrátor deleguje na specializované agenty, každý se svým harness kontextem.
Pravidlo palce

Pokud agent dělá špatné věci → problém je v guardrails. Pokud agent dělá generické věci → problém je v harness.

6 — Nejčastější nepochopení

Co si lidé myslí

"Guardrails jsou to, co AI firma nastavila. Já je nemohu ovlivnit."

Co to skutečně je

V Claude Code jsou guardrails tvoje — píšeš je ty jako shellové skripty v settings.json. Anthropic má vlastní policy-level guardrails (model refuses), ale to je jiná vrstva. Lokální guardrails jsou pod tvou kontrolou a jsou deterministické — nespoléhají na to, že model "odmítne".

Druhé nepochopení

"Víc guardrails = bezpečnější agent."

Skutečnost

Přehnaně omezený agent je zbytečný — to je "OH NO" extrém (B8 — Vibe vs. AI-assisted). Guardrails bez dobrého harness znamená: agent nic nezkazí, ale taky nic neudělá. Cíl je rovnováha — silný harness (agent ví, co dělat) + cílené guardrails (agent nemůže způsobit katastrofu).

7 — Spicy teze

Většina týmů investuje čas do guardrails, protože selhání jsou viditelná. Harness ignorují, protože špatný harness selže tiše — agent prostě dělá průměrné věci a tým si myslí, že AI je přeceňovaná.

8 — Primární zdroje

  • Claude Code Docs — Hooks Proč: přesná specifikace hooku, exit code 2, event typy. Primární zdroj pro guardrails část. Přečti celou stránku — je krátká.
  • Claude Code Docs — Memory Proč: CLAUDE.md je hlavní harness komponent. Tato stránka vysvětluje hierarchii (global / projekt / local) a co patří kam.
  • Claude Code Docs — Settings & Permissions Proč: permission system (allowedTools, blockedTools) je druhý hlavní guardrail mechanismus. Ukazuje, jak se harness a guardrails konfigurují ze stejného místa.

9 — Páteř 🎯

Jádro nastudeno — jedna věta, ze které odvodíš skoro cokoli, a tři kotvy, co si držíš. Když zamrzneš, vrať se sem.

  • palecPravidlo palce: dělá špatné věci → oprav guardrails; dělá generické věci → oprav harness.
Přenosný test — kam co patří

U každé věci se zeptej: „Přidává to agentovi schopnost, nebo mu něco zakazuje?"
Přidává schopnost → harness (CLAUDE.md, skills, MCP, memory).
Zakazuje akci → guardrail (hook, permission).

10 — Až se tě zeptají 🎤

Ostré dotazy z publika + krátká odpověď s pointou (tučně). Trénuj nahlas, ne čtením.

Námitka „guardrails": „Guardrails si přece nastavuje Anthropic, do toho já nevidím."

V Claude Code jsou guardrails tvoje — píšeš je jako shell skripty v settings.json (hooks, permissions). Anthropic má vlastní policy vrstvu (model odmítne), to je něco jiného. Lokální guardrails jsou deterministické a pod tvou kontrolou.

Námitka „víc = líp": „Čím víc guardrails, tím bezpečnější agent, ne?"

Ne. Přehnaně omezený agent nic nezkazí, ale taky nic neudělá (extrém „OH NO"). Cíl je rovnováha: silný harness (agent ví, co dělat) + cílené guardrails (nemůže způsobit katastrofu).

Chyták „prompt": „Není harness jen fajnové slovo pro prompt?"

Prompt je jen část. Harness je celé trvalé prostředí: CLAUDE.md (paměť), skills, MCP nástroje, konfigurace — platí napříč sezeními, není to jednorázová věta.

Námitka „model si odmítne sám": „Proč guardrails, když model umí nebezpečnou věc odmítnout?"

Protože model je pravděpodobnostní — občas odmítne, občas ne, halucinuje. Hook běží v Bashi mimo model: buď projde, nebo ne. Na bezpečnost potřebuješ determinismus, ne dobrou vůli modelu.

Námitka „je to k ničemu": „Nasadili jsme AI a nedělá nic užitečného pro náš projekt — je přeceňovaná."

Nejspíš máš prázdný harness. Agent nemá kontext domény, tak dává generický průměr. Chybí mu CLAUDE.md, nástroje, doménová paměť — není to vada modelu.

Otázka „jak to poznám": „Jak zjistím, jestli je problém v harness, nebo v guardrails?"

Pravidlo palce: dělá nebezpečné/špatné věci → guardrails. Dělá bezpečné, ale generické/k ničemu věci → harness.
