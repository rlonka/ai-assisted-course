C1 Týden 6 Blok C: Vědecký software

FAIR4RS

FAIR principy pro vědecký software, ne jen pro data. Findable, Accessible, Interoperable, Reusable — a proč se to nedá zkopírovat z dat jedna ku jedné.

1 — Jádro

Reprodukovatelnost (C2) byla o tom, aby tvůj výsledek přežil. FAIR4RS je o tom, aby přežil a byl použitelný pro ostatní tvůj software. FAIR = Findable, Accessible, Interoperable, Reusable — čtyři principy, které rozhodují, jestli je tvůj kód dohledatelný, dostupný, propojitelný a znovupoužitelný, nebo jestli zmizí i s tebou.

FAIR vznikl pro data (Wilkinson et al., 2016). Software je ale jiné zvíře — spustitelný, závislý na verzích, vyvíjí se v čase. Proto vznikl FAIR4RS (RDA/ReSA/FORCE11, 2022): FAIR principy přizpůsobené výzkumnému softwaru. Pro RSE komunitu je to profesní standard — a AI ho činí zároveň snadnějším i naléhavějším.

Jedno pravidlo

FAIR není o zveřejnění kódu. Je o tom, aby ho stroj i člověk našel, dostal se k němu, propojil ho a znovu použil — bez tebe jako prostředníka. Software, který umíš spustit jen ty, není vědecký nástroj; je to tvůj osobní skript.

2 — Proč software nestačí FAIR pro data

FAIR pro data se nedá na software přenést jedna ku jedné, protože software má vlastnosti, které data nemají:

Vlastnost Data Software
Povaha Statická — jednou pořízená Spustitelná — něco dělá
Závislosti Zpravidla žádné Prostředí, knihovny, verze
Vývoj v čase Verze = nový dataset Neustálý — commity, release, forky
„Použít" Přečíst / analyzovat Zkompilovat, spustit, integrovat

Proto FAIR4RS klade důraz na věci, které u dat nedávají smysl: verzování s persistentními identifikátory pro každou verzi, popis závislostí a prostředí, citovatelnost vyvíjejícího se artefaktu, licenci umožňující spuštění a úpravu. Reprodukovatelnost z C2 je tady jádrem principu „Reusable".

3 — Čtyři principy pro software

FFindable

Software i jeho metadata jsou dohledatelné — mají persistentní identifikátor a jsou registrované/indexované.

V praxi DOI přes Zenodo, záznam v registru, bohatá metadata (autoři, verze, klíčová slova).
AAccessible

Software lze získat standardním protokolem; metadata přežijí, i kdyby samotný kód zmizel.

V praxi Veřejný repozitář, archivovaný release, jasně definovaný způsob přístupu (i s autentizací).
IInteroperable

Čte a píše standardní formáty, používá komunitní API, propojí se s dalším softwarem a daty.

V praxi Standardní vstup/výstup (HDF5, NetCDF…), dokumentované API, žádné proprietární black-boxy.
RReusable

Jasná licence, provenience, dokumentace a komunitní standardy — aby na tom šlo stavět.

V praxi LICENSE, CITATION.cff, testy, reprodukovatelnost (C2), popis prostředí a závislostí.

Principy jsou pořadím záměrné: nejdřív tě musí najít (F), pak získat (A), pak to musí zapadnout do jejich ekosystému (I), teprve pak na tom mohou stavět (R). Přeskočit dřívější znamená, že pozdější je k ničemu — nejlepší znovupoužitelný kód je bezcenný, když ho nikdo nenajde.

4 — Nejdůležitější rozlišení: FAIR ≠ Open

FAIR = Open Source
Accessible neznamená „zdarma a veřejně". Znamená „získatelné definovaným protokolem — i s autentizací".

Tohle je nejčastější a nejzávažnější nepochopení. FAIR nemluví o ceně ani o otevřenosti — mluví o dohledatelnosti a definovaném přístupu. Software za autentizací, komerční nebo s omezenou licencí může být plně FAIR, pokud má persistentní identifikátor, jasně popsaný způsob přístupu a metadata, která přežijí. A naopak: kód volně na GitHubu bez licence, bez metadat, bez identifikátoru je open, ale ne FAIR — nenajdeš ho, nesmíš ho legálně použít, a za rok bude smazaný.

Zapamatuj si

Open je o právech a ceně. FAIR je o nalezitelnosti a přístupu — pro stroje i lidi. Můžeš být FAIR bez toho být open; a být open bez toho být FAIR. Cíl vědeckého softwaru je FAIR; open je časté, ale ne totéž.

5 — FAIR a agenti: metadata jsou strojová potrava

Původní FAIR měl silný důraz, který se často zapomíná: má být machine-actionable — čitelný a použitelný nejen pro člověka, ale pro stroj. V éře agentů to přestává být abstraktní ideál a stává se praktickou pákou, obousměrně:

  • FAIR je to, co agentovi umožní tvůj software použít. Strojově čitelná metadata, standardní rozhraní (I) a jasná licence (R) jsou přesně to, co agent (a MCP server, B6) potřebuje, aby tvůj nástroj našel a zapojil. Ne-FAIR software je pro agenta neviditelný.
  • Agent ti pomůže software zFAIRovatit. Vygenerovat CITATION.cff, doplnit licenci, napsat metadata, standardizovat vstup/výstup, sepsat dokumentaci — to je přesně nudné plumbing, které vědci odkládají a agent zvládne neúnavně.
# CITATION.cff — strojově čitelná metadata (princip F + R) cff-version: 1.2.0 title: particle-sim version: 2.1.0 doi: 10.5281/zenodo.1234567 license: MIT authors: - family-names: Novák given-names: Jan

Ale pozor na druhou stranu: agenti vyrábějí software rychleji než kdy dřív — a tím i ne-FAIR software rychleji než kdy dřív. Skripty bez licence, bez metadat, bez identifikátoru se hromadí průmyslovým tempem. FAIR se proto z „hezké ctnosti" mění na nutnou hygienu, jinak se vědecký software utopí v nedohledatelném balastu.

6 — Kolik FAIR je dost

Minimum pro každý projekt ✓

  • LICENSE — bez ní nesmí nikdo legálně použít (R)
  • README s popisem a spuštěním (F, R)
  • Připnuté závislosti / prostředí (R, C2)
  • Verejný repozitář s historií (A)

Když jde o vědecký výstup navíc ✓

  • DOI přes Zenodo pro citovatelnost (F)
  • CITATION.cff — strojová metadata (F, R)
  • Standardní vstup/výstup formáty (I)
  • /reproduce a testy invariantů (R, C2)

FAIR není binární přepínač, je to spektrum — a jde po něm postupovat po krocích jako po žebříku reprodukovatelnosti (C2). Ale jedna věc je nepodkročitelné minimum: LICENSE. Kód bez licence není „volný" — je ve výchozím stavu zapovězený (autorské právo). Nejčastější tichý blocker znovupoužití není chybějící DOI, ale chybějící řádek s licencí.

7 — Historický kontext

  • FAIR data principles (Wilkinson et al., 2016). Původní text, ohromně vlivný, ale explicitně o datech. Zavedl machine-actionability jako cíl. FAIR4RS je jeho adaptace — se všemi rozdíly, které software přináší.
  • FAIR4RS Working Group (Chue Hong et al., 2022). RDA + ReSA + FORCE11. Komunitní konsenzus, jak FAIR aplikovat na software. Primární zdroj této lekce a profesní standard RSE.
  • Software citation principles (FORCE11, 2016) a CITATION.cff. Konkrétní řešení, jak software citovat a popsat strojově. Praktická náplň principů F a R.
  • RSE hnutí a Software Sustainability Institute. Celé profesní hnutí kolem toho, že vědecký software si zaslouží stejnou péči jako vědecká data. Nordic-RSE, ReSA — komunita, která FAIR4RS drží při životě.

Pointa pro publikum (a pro RSE zvlášť): FAIR4RS je uznání, že software je první-třídní vědecký výstup, ne pomocný skript. To je celý étos RSE profese — a AI, která software zlevňuje, ten étos nezastarává, naopak: čím víc kódu, tím důležitější, aby byl dohledatelný a použitelný.

8 — Tři příklady

Vědec-kodér

Napsal užitečný analytický nástroj, dal ho na GitHub — a považuje ho za „sdílený". Jenže: bez licence (nikdo ho legálně nesmí použít), bez metadat (nikdo ho nenajde), bez popisu prostředí (nikdo ho nespustí). Open, ale ne FAIR. Nechá agenta doplnit LICENSE, CITATION.cff a README, archivuje release na Zenodo pro DOI — a z osobního skriptu se stane citovatelný vědecký nástroj.

RSE vývojář

FAIR4RS je jeho profesní řemeslo. Zavádí ho jako standard skupiny: každý projekt má LICENSE, CITATION.cff, standardní I/O formáty, DOI pro release. Ví, že FAIR ≠ open — jejich clusterový nástroj je za autentizací, ale je plně FAIR díky persistentnímu identifikátoru a popsanému přístupu. AI používá na plumbing, člověk hlídá, že metadata jsou pravdivá, ne halucinovaná.

Manažer / PI

Grantová agentura čím dál častěji vyžaduje FAIR software management plan. PI, který to bral jako byrokracii, zjišťuje, že FAIR je návratná investice: FAIR software se cituje (impact), přežije odchod studenta (kontinuita) a je připravený pro agentní nástroje (budoucnost). Metrika není „máme open source", ale „najde a použije naše nástroje někdo — nebo agent — bez nás?".

9 — Propojení na ostatní lekce

  • C2 — Reprodukovatelnost: Reprodukovatelnost je jádro principu „Reusable". FAIR4RS zasazuje C2 do širšího rámce — reprodukovatelný, ale nenalezitelný software je pořád k ničemu pro ostatní.
  • B6 — MCP: Machine-actionable metadata jsou to, co agentovi (přes MCP server) umožní tvůj software najít a použít. FAIR software je agentem použitelný software; ne-FAIR je pro něj neviditelný.
  • A4 — Domain-Driven Design: Interoperabilita (I) i metadata staví na sdíleném jazyce domény. Standardní formáty a API jsou ubiquitous language mezi nástroji — totéž, co CLAUDE.md řeší uvnitř projektu.
  • C3 — Deskilling: FAIR vyžaduje rozumět vlastnímu softwaru natolik, abys ho popsal a udělal použitelným. Je to další tlak proti erozi — nedokumentuješ FAIR, čemu sám nerozumíš.

10 — Nejčastější nepochopení

Nepochopení 1

„Dal jsem kód na GitHub, takže je FAIR."

Skutečnost

GitHub bez licence, metadat a identifikátoru je open, ale ne FAIR. Nenajdeš ho (žádný DOI, chudá metadata), nesmíš ho legálně použít (bez licence je defaultně zapovězený), a může být kdykoliv smazán (žádný archivovaný release). Zveřejnění je nutná, ale zdaleka ne dostatečná podmínka. FAIR je o nalezitelnosti a použitelnosti, ne o tom, že je to „venku".

Nepochopení 2

„FAIR znamená, že to musím dát zadarmo a otevřeně — to nemůžu, náš software je komerční / za autentizací."

Skutečnost

FAIR ≠ open. Accessible znamená „získatelné definovaným protokolem", ne „zdarma a veřejně" — přístup smí zahrnovat autentizaci nebo licenci. Komerční či chráněný software může být plně FAIR, pokud má persistentní identifikátor, popsaný způsob přístupu a trvalá metadata. Otevřenost je jiná osa než FAIR.

Nepochopení 3

„FAIR je jen pro data — pro pár skriptů je to zbytečná byrokracie."

Skutečnost

Právě proto vznikl FAIR4RS — software je jiné zvíře než data a zaslouží vlastní adaptaci, ne odmítnutí. A minimum není byrokracie: LICENSE + README + připnuté prostředí je pár hodin práce (s agentem méně), které rozhodují, jestli tvůj „pár skriptů" přežije tvůj odchod, nebo zmizí. Byrokracie je forma bez užitku; FAIR minimum je užitek bez formy.

11 — Spicy teze

Většina vědeckého softwaru na světě je mrtvá při narození — jeden autor ho umí spustit, nikdo jiný ho nenajde, a s odchodem autora mizí. Není to problém talentu ani nástrojů; je to problém, že věda odměňuje papery, ne použitelný kód. FAIR4RS je pokus tenhle nesoulad napravit zvenčí — a AI je první síla, která ho může vyřešit zevnitř, protože zlevňuje přesně ten plumbing, na který nikdy nebyl čas. Kdo dnes vydá ne-FAIR software, nešetří čas. Odkládá pohřeb.

12 — Primární zdroje

  • FAIR Principles for Research Software (FAIR4RS) — Chue Hong et al. (2022) Proč: Primární zdroj. Definitivní komunitní dokument (RDA/ReSA/FORCE11). Přečti čtyři principy a sekci o tom, čím se software liší od dat. Základ celé lekce a profesní standard RSE.
  • The FAIR Guiding Principles — Wilkinson et al. (2016) Proč: Původní FAIR (pro data). Pochopíš, odkud principy pocházejí a proč je machine-actionability jádro — klíčové pro pochopení, proč FAIR software = agentem použitelný software. Čti úvod a definice.
  • Citation File Format (CITATION.cff) Proč: Praktický nástroj pro principy F a R — strojově čitelná metadata a citace softwaru. Konkrétní, hned použitelné. Ukázka, že FAIR minimum je řádky v souboru, ne byrokracie.

13 — Feynmanovo cvičení

Feynmanův test — FAIR4RS
1. Kolega dal skript na veřejný GitHub bez licence a bez dalších metadat a tvrdí, že je teď FAIR. Má pravdu?
2. Váš clusterový nástroj je za autentizací a nemůže být veřejně otevřený. Může být FAIR?
3. Proč je FAIR (a machine-actionable metadata) v éře agentů obzvlášť důležité?
4. Jaké je nepodkročitelné minimum FAIR, které nejčastěji tiše blokuje znovupoužití, když chybí?

14 — Co dál

Co musíš znát před touto lekcí:

  • C2 — Reprodukovatelnost — jádro principu „Reusable". FAIR4RS ji zasazuje do širšího rámce.
  • B6 — MCP — machine-actionable metadata jsou to, co agentovi umožní tvůj FAIR software použít.

Praktický úkol (25 minut): Vezmi jeden svůj repozitář a projdi ho podle F/A/I/R. Konkrétně: má LICENSE? Má README s popisem a spuštěním? Má CITATION.cff? Používá standardní I/O formáty? Nech agenta doplnit, co chybí z minima (LICENSE, CITATION.cff, README), a ověř, že metadata jsou pravdivá — ne halucinovaná. Pak si polož otázku PI: „Najde a použije tenhle nástroj někdo bez mého vysvětlení?"

Konec jádra bloku C. Máš teď rámec vědecké kvality: reprodukovatelnost (C2), FAIR (C1), a jejich lidský protipól — deskilling (C3) a trust gap (C4). Umíš říct, co dělá vědecký software důvěryhodným a použitelným, a kde AI pomáhá i škodí.
