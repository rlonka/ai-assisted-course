B9 Týden 3 Blok B: Agentní paradigma

Agentní smyčka

Jak agent běží v čase — od zadání po hotovo, krok po kroku

1 — Jádro

Agentní práce není jednorázová odpověď — je to cyklus. Chatbot dostane prompt a vrátí text; tím končí. Agent naproti tomu běží ve smyčce: model dostane kontext, rozhodne jednu akci (spustit nástroj), ta se vykoná mimo model, její výsledek se vrátí zpět do kontextu — a model se ptá znovu, co dál. Smyčka běží, dokud model neusoudí, že je hotovo. Zásadní posun: řídící tok neurčuje programátor předem, ale model za běhu. To je celá síla i celé riziko agentního paradigmatu.

Proč to musíš umět přednášet

Publikum často slyší „AI agent" a představí si chytřejší chatbot. Rozdíl ale není inteligence — je to smyčka: agent koná a iteruje. Bez téhle mentální mapy nedává smysl, proč jsou guardrails (B1) a verifikace (D2) najednou tak důležité. Kdo pochopí smyčku, pochopí celý blok B.

Slovníček — pár slov, bez kterých smyčka nedává smysl

co agent dělá
  • Tool call — model požádá „spusť nástroj X s argumenty Y" (přečti soubor, spusť bash, edituj řádek)
  • Tool result — co nástroj vrátil (stdout, obsah, chyba); přidá se do kontextu
  • Krok / iterace — jeden průchod smyčkou: model → nástroj → výsledek
co si nesplést
  • Agent ≠ chatbot — chatbot jen odpoví textem; agent koná a iteruje
  • Kontextové okno — vše, co model „vidí" v daném kroku; skládá se znovu každou iteraci
  • Řídící tok — pořadí kroků; u agenta ho určuje model za běhu, ne napsaný kód

2 — Historický kontext

Rozdíl mezi „program" a „agent" je v tom, kdo určuje pořadí kroků:

  • Klasický program — řídící tok napíše programátor (if, for, volání funkcí). Pořadí je pevné a deterministické. Stroj dělá přesně to, co je napsáno.
  • Chatbot (2022, ChatGPT) — jeden průchod: prompt → odpověď. Žádné akce, žádná iterace. Mocné, ale pasivní.
  • Tool use / function calling (2023) — model umí požádat o zavolání funkce. Když kolem toho postavíš smyčku, vznikne agent.
  • Autonomní agenti (2023: AutoGPT, BabyAGI) — první populární „agent loops". Často se zacyklily nebo ztratily cíl — ukázaly, že smyčka bez mantinelů je křehká.
  • Claude Code (2025) — vyladěná smyčka pro práci s kódem: nástroje na soubory/bash, guardrails, kontext z CLAUDE.md.
Akademická kotva — ReAct (Yao et al., 2022)

Vzor ReAct (Reason + Act) formalizoval, co dnes dělá každý agent: prokládat uvažování a akce — Thought → Action → Observation → Thought → … Model si „nahlas" rozmyslí krok, provede ho, přečte výsledek, a podle něj plánuje dál. Agentní smyčka je ReAct v praxi.

Co je nové: po desetiletí platilo, že sekvenci kroků napíše člověk dopředu. Agent tuhle sekvenci rozhoduje za běhu — podle toho, co viděl v předchozím kroku. Přesně proto je nepředvídatelnější než program (a proto potřebuje guardrails).

3 — Smyčka krok po kroku

Co se stane od chvíle, kdy odešleš zadání, po „hotovo":

1 ZadáníUživatel napíše prompt / příkaz — nebo to spustí trigger (hook, naplánovaná úloha).
↓
2 Sestavení kontextu (harness)Systém složí kontextové okno: system prompt + CLAUDE.md + historie konverzace + definice dostupných nástrojů + výstupy z minulých kroků.
↓
3 Inference modeluModel dostane celé okno a vygeneruje jednu věc: buď (a) finální text uživateli → smyčka končí, nebo (b) tool call → pokračuje krokem 4.
↓  (tool call)
4 Guardrails / permissionsNež se nástroj spustí, projde kontrolou (permission systém, hooks). Buď povolí, zeptá se tebe, nebo zablokuje (exit 2). Běží mimo model.
↓
5 Vykonání nástrojeNástroj se spustí mimo model (bash proces, čtení disku, HTTP na MCP server) a vrátí výsledek: stdout, obsah souboru, nebo chybu.
↓
6 Výsledek zpět do kontextuVýstup nástroje se přidá do kontextového okna jako nová zpráva („tool result").
↑ zpět na krok 3 — model dostane rozšířené okno a rozhodne další krok. Smyčka běží dál.
✓ Když model v kroku 3 vrátí finální text (bez tool callu) → HOTOVO
Kde smyčka skončí

Cyklus 3 → 6 běží dokola, dokud nenastane jedno ze tří:

  • Model řekne „hotovo" — v kroku 3 vrátí finální text bez tool callu.
  • Strop — narazí na limit (počet kroků, tokenů). Pojistka proti zacyklení.
  • Přerušení — zastavíš to ty.
Klíčový detail, který publikum přehlédne

Kontext se v kroku 2 skládá znovu při každé iteraci — ne jen jednou na začátku. Proto CLAUDE.md a nastavené nástroje ovlivňují každý krok smyčky, ne jen ten první. A proto s délkou smyčky roste kontextové okno (a tím i náklady i riziko, že se v něm ztratí to podstatné — viz D1 context engineering).

4 — Tři příklady

Vědec-kodér

„Oprav bug v solveru." Smyčka: přečte soubor (nástroj) → spustí test (nástroj, selže) → přečte traceback (výsledek) → edituje řádek (nástroj) → spustí test znovu (projde) → finální text „hotovo". Čtyři iterace, každá s vlastním rozhodnutím — žádnou z nich jsi nenapsal dopředu.

RSE vývojář

Agent na HPC: přečte SLURM konfiguraci (MCP nástroj) → navrhne skript → chce spustit sbatch → guardrail v kroku 4 povolí jen --test-only (dry-run) → přečte výstup → opraví. Smyčka běží, ale mantinel drží ostré spuštění za schválením.

Manažer / PI

Proč „agent" ≠ „chatbot": chatbot ti dá text, který zkopíruješ. Agent sám sáhne do repa, spustí testy, upraví soubory, commitne. Víc síly = víc potřeba guardrails a verifikace. Autonomie roste s délkou smyčky — a s ní odpovědnost za dohled.

5 — Propojení na zbytek kurzu

  • B1 — Harness vs. Guardrails: harness = krok 2 (sestavení kontextu), guardrails = krok 4 (brána před akcí). B9 ukazuje, kdy ve smyčce každý z nich zasáhne.
  • B8 — Vibe vs. AI-assisted: vibe = kolik iterací smyčky pustíš bez čtení výsledků. Čím delší nekontrolovaná smyčka, tím hlouběji ve vibe.
  • B7 — Subagenti: smyčka uvnitř smyčky — orchestrátor v jednom kroku spustí podagenta, který má vlastní kompletní smyčku.
  • C4 — Trust gap: každá iterace může zanést tiše špatný výsledek. Delší smyčka = víc míst, kde se chyba schová.
  • D1 — Context engineering: kontext se skládá v kroku 2 každou iteraci — kurátorství toho okna je proto zásadní dovednost.
Pravidlo palce

Chceš vědět, jestli něco je „agent"? Zeptej se: koná to a opakuje se to (volá nástroje, čte výsledky, plánuje další krok)? Pak je to agentní smyčka. Když to jen jednou odpoví textem, je to chatbot.

6 — Nejčastější nepochopení

Co si lidé myslí

„Agent je jen chytřejší chatbot."

Co to skutečně je

Rozdíl není inteligence modelu — je to smyčka. Agent koná (volá nástroje) a iteruje (čte výsledky, plánuje další krok). Tentýž model může fungovat jako pasivní chatbot i jako aktivní agent — liší se, jestli kolem něj běží smyčka s nástroji.

Druhé nepochopení

„Agent běží podle skriptu, který někdo napsal."

Skutečnost

Řídící tok — pořadí kroků — rozhoduje model za běhu, podle výsledků. Programátor dodal jen nástroje (harness) a mantinely (guardrails), ne sekvenci. Přesně proto je agent nepředvídatelnější než klasický program a přesně proto potřebuje guardrails.

Třetí nepochopení — „Když agent pracuje sám, můžu odejít"

Čím delší smyčka běží bez tvého pohledu, tím víc prostoru pro tiše špatný výsledek, který se řetězí do dalších kroků. Autonomie agenta není absence tvé odpovědnosti — je to důvod, proč nastavit mantinely a kontrolní body dřív, než ho pustíš.

7 — Spicy teze

Klasický software dělá přesně to, co jsi napsal. Agent dělá to, co se v každém kroku sám rozhodne. Řídící tok se přestěhoval z tvého kódu do modelu — a to je celá revoluce i celé riziko v jedné větě. Kdo to nepochopí, buď agentovi slepě věří, nebo se ho zbytečně bojí.

9 — Páteř 🎯

Jádro nastudeno — jedna věta, ze které odvodíš skoro cokoli, a tři kotvy, co si držíš. Když zamrzneš, vrať se sem.

Agent = model v cyklu, který sám volí a řetězí kroky. Sekvence: sestav kontext → inference → (tool call → guardrail → nástroj → výsledek zpět) → znovu, dokud není hotovo. Řídící tok neurčuje programátor předem, ale model za běhu.

  • cyklusChatbot = 1 průchod (prompt→odpověď). Agent = smyčka model→nástroj→výsledek→model, dokud není hotovo.
  • ReActVzor Reason+Act: Thought → Action → Observation, opakovaně (Yao et al., 2022).
  • kdo řídíPořadí kroků rozhoduje model za běhu, ne napsaný kód → nepředvídatelné → proto guardrails.
Přenosný test — je to agent, nebo program?

„Kdo rozhodl, který krok přijde teď — programátor předem, nebo model za běhu?"
Programátor předem → klasický program (pevný řídící tok).
Model za běhu, podle výsledků → agentní smyčka.

10 — Až se tě zeptají 🎤

Ostré dotazy z publika + krátká odpověď s pointou (tučně). Trénuj nahlas, ne čtením.

Otázka „v čem je rozdíl": „Čím se agent liší od ChatGPT?"

Chatbot dá text a končí. Agent v cyklu volá nástroje, čte výsledky a plánuje další krok, dokud není úkol hotový. Rozdíl je konání a iterace, ne inteligence.

Otázka „kdo to napsal": „Kdo naprogramoval, co agent v jakém pořadí udělá?"

Nikdo předem. Řídící tok rozhoduje model za běhu podle výsledků. Programátor dodal jen nástroje (harness) a mantinely (guardrails), ne sekvenci kroků.

Otázka „kde to skončí": „Jak agent pozná, že má přestat?"

Když v kroku inference vrátí finální text bez tool callu (usoudí, že hotovo). Nebo narazí na limit kroků/tokenů, nebo ho přerušíš ty.

Námitka „nezacyklí se to": „Nemůže se agent točit donekonečna?"

Může — proto existují limity kroků a guardrails. Rané agenty (AutoGPT, 2023) se zacyklovaly běžně. Produkční smyčky mají stopky a kontrolní body.

Otázka „proč nebezpečnější": „Proč je agent rizikovější než chatbot?"

Protože koná (mění soubory, spouští příkazy) a dělá to opakovaně bez schválení každého kroku. Víc síly → víc potřeba guardrails (B1) a verifikace (D2).

Otázka „kam patří CLAUDE.md": „Kde do smyčky vstupuje CLAUDE.md a nástroje?"

V kroku 2 (sestavení kontextu) — a to se děje každou iteraci znovu, ne jen na začátku. Proto CLAUDE.md ovlivňuje každý krok smyčky.
